# Agent Note: Desktop panel resize without limits, with persisted geometry

Status: implemented

## Problem
The sidebar, details, and desktop right (browser) panels each carried hand-picked min/max widths (`SIDEBAR_MIN`/`MAX`, `DETAILS_MIN`/`MAX`, a details `CENTER_MIN` floor protecting the center column, and a browser-panel `Math.max(420, floor(viewport*2/3))` ceiling). None of those numbers reflected a real constraint — they were arbitrary caps a user with a wide monitor or a specific workflow had no way to lift. Geometry also lived in memory only: reloading the page reset every panel back to its default width. The desktop title bar additionally carried its own sidebar-toggle button that duplicated the sidebar's own collapsed-rail toggle, leaving two controls for one action with only one of them fully interactive.

## Decision
`columns.ts` now solves widths with no protected floor or ceiling beyond the physical viewport: `computeColumns` caps a column only at the space actually available (never wider than the viewport; details never wider than what the sidebar leaves behind) and lets the center column shrink to zero. `SIDEBAR_MIN`/`SIDEBAR_MAX`/`DETAILS_MIN`/`DETAILS_MAX`/`CENTER_MIN` are gone. In their place, `SIDEBAR_COLLAPSE_BELOW` (160) and `DETAILS_COLLAPSE_BELOW` (200) live in the layout store (`stores.ts`): `setSidebar`/`setDetails` snap the preference to 0 (closed) once a drag or keyboard step crosses the threshold, otherwise they keep the exact dragged pixel width verbatim. The desktop-only right (browser) panel in `AppFrame.tsx` follows the same shape — `DESKTOP_BROWSER_COLLAPSE_BELOW` (240) replaces the old `DESKTOP_BROWSER_MIN` floor and the two-thirds-viewport ceiling is gone; a drag or step below the threshold closes the panel (`setBrowserOpen(false)`) instead of clamping, and the rendered width is capped only by `desktopViewport.width`. The layout store's whole state (`sidebar`, `details`, `narrow`, `narrowExpanded`) persists to `localStorage` under `hydra.layout.panels` via the store engine's `persist` option, so a reload restores the last-dragged sizes instead of resetting to contract defaults. The desktop title bar (`DesktopTitleBar.tsx`) dropped its own sidebar-toggle button and `sidebarOpen` prop entirely — Ctrl+B and the View menu still call `toggleSidebar()` directly — leaving the sidebar's own collapsed-rail control (which already swaps a logo mark for the panel icon on hover) as the single interactive toggle, matching the web shell.

## Alternatives considered
**Keep a floor but raise it** was rejected: any fixed number is still an opinion a future workflow can outgrow, and the collapse-below threshold already gives a graceful "too small to be useful" outcome without needing a magic width. **Clamp the drag but let keyboard steps escape it** was rejected for consistency — a keyboard user and a mouse user should hit the identical boundary. **A separate persisted key per panel** was rejected in favor of one whole-state key (`hydra.layout.panels`): the store engine persists the full state object already, and splitting it would need per-field migration logic for a state shape this small. **Disabling (not removing) the title bar's redundant toggle** was rejected per explicit user direction: a disabled duplicate is still a second thing to explain, and the sidebar's own control already does the job.

## Consequences
A user can drag or step the sidebar, details, or right panel to any width up to the physical viewport; the only way to make one disappear is to cross its collapse threshold, at which point it closes instead of sitting at an unusably thin fixed floor. Reopening the app after a reload keeps the panel widths from the previous session. The desktop title bar has one fewer button; its keyboard shortcut and menu entry are unaffected. Known gap: the desktop shell launches its local server on an OS-assigned port (`--port 0`) on every run, and `localStorage` is scoped per origin+port, so `hydra.layout.panels` (and every other renderer-persisted key) survives an in-session reload but not a real app relaunch — a stable port or an IPC-based settings bridge would be needed to close that gap, and neither exists yet.

## Verification
`columns.client.spec.ts` and `layout-store.client.spec.ts` were rewritten for the no-ceiling/no-floor model, including a persistence round trip (`createLayoutStore().create()` twice against the same `localStorage` key). `app-frame.client.spec.tsx` pins drag and keyboard-step behavior for all three panels against the new formulas, including the browser panel's collapse-on-drag-below-threshold and its viewport-only cap, and `desktop-title-bar.client.spec.tsx` confirms the toggle button is gone while Ctrl+B still dispatches `toggle-sidebar`. Live-verified in a real Electron instance via CDP: stepping the right panel with the keyboard grows it to the full window width with no intermediate ceiling, and stepping it back down crosses the threshold and closes the panel.
