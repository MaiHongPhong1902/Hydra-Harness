## Verified limits and gaps

PI has no structured Delete/Move tool in this path. Its finalizer and rollback support deletion, tested by deleting the target between prepare and finalize. Bash/script/formatter/git-apply writes are not captured: `tool_operation` only matches Write/Edit. External editor changes are not history entries; their changed bytes cause hash conflicts. Binary files can have a reversible raw snapshot with no text preview. Files above 16 MiB have hashes but no before copy, so overwrites are not reversible; a large newly created file can still be removed after hash validation.

Snapshot preparation failures log a warning and do not prevent the tool. Finalization failures discard the snapshot even if the mutation succeeded. A crash before metadata publication can leave a `before` file with no record; there is no automatic filesystem restoration. A crash between restoration and metadata update can make retry conflict. PI's afterHash guard does not provide atomic compare-and-swap against an unrelated external writer racing after the hash check.

## PI tests inspected

`crates/host-core/src/review.rs`: `records_line_changes_and_rolls_back_without_git`, `refuses_to_overwrite_a_later_edit`, `added_file_rollback_removes_the_file`, `deleted_file_rollback_restores_previous_bytes`. `apps/desktop/test/chat-review-entry.test.mjs` tests successful message ownership, failed/scratch exclusion, chronological history without Git, inline/panel wiring and accessibility. `permissions.rs::accept_edits_allows_file_tools_only` distinguishes permissions from review acceptance. These are source-inspected tests; execution results are reported separately.
